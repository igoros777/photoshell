# Security Policy

## Scope and Supported Versions

This is a small scripts repository with no packaged releases.

Security fixes are applied to:

- the default branch (`main`)
- the latest versions of scripts and docs in this repository

Older snapshots, forks, and local copies are not actively supported.

## Reporting a Vulnerability

Please use GitHub contact methods first.

Preferred (private):

1. Go to the repository **Security** tab.
2. Click **Report a vulnerability** and submit a private report.

If private reporting is unavailable, open a GitHub issue and clearly mark it as security-related.

Public/non-sensitive issues:

- Open a regular GitHub issue in this repository and include `[security]` in the title.

General contact via GitHub:

- Open a GitHub Discussion (if enabled) or mention `@igoros777` in an issue.

## What to Include

Please include:

- affected script/file and commit/branch (if known)
- clear reproduction steps
- impact and severity estimate
- proof-of-concept or sample command/input (sanitized)
- any suggested fix or mitigation (optional)

## Response Process

- Initial triage response target: within 7 days
- Status updates target: at least every 14 days while the report is open
- If confirmed, a fix will be prepared and merged to `main` as soon as practical
- Credit can be provided in release notes/commit messages if requested

## Safe Harbor

Good-faith security research is welcome.

Please avoid:

- accessing or modifying data you do not own
- service disruption (DoS, destructive testing)
- sharing sensitive details publicly before a fix is available
